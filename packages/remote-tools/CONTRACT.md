# Cooperative destination contract — R03–R05

Selected local implementation contract. Real effects remain synthetic; existing E1–E5 histories retain their meanings. Root owns final acceptance.

A destination pins a deployment domain, coordinator Ed25519 public key and its own service identity/key. The trusted application holds the coordinator signing key; agents never receive it, provider credentials or arbitrary endpoint choices. JSON requests are bounded, data-only, strict-key checked, signed over canonical data under a request domain separator. Responses are signed by the pinned service and bind the entire request digest, unique request nonce and current destination sequence. Authentication is not provider honesty or confidentiality; HTTPS is required for non-loopback deployments and this implementation initially accepts loopback HTTP only.

Wire request body exactly {version:'continuity-cooperative-request/1', serviceId, nonce, operation, payload}; envelope {body,signature}. Operations: checkpoint, prepare, commit, status, cancel. Each request is signed by coordinator. Each response body exactly {version:'continuity-cooperative-response/1',serviceId,requestDigest,sequence,result}; envelope {body,signature}. Responses sign the complete body and the client verifies exact service, request digest, shape/signature before use. Digest is sha256 of Core canonical data encoding. No redirects; finite body/time limits. HTTP error is never evidence of cancellation.

Destination API createCooperativeDestination({directory,domain,serviceId,coordinatorPublicKey,servicePrivateKey,now,validateOperation}) -> {url,close,inspect}. now and validateOperation are trusted fixed application configuration, never request data. validateOperation(events, operation, now, destinationState) is synchronous and returns captured {intentId,idempotencyKey,submissionFingerprint,tool,arguments,businessKey,contractId}; throws to refuse. Root supplies actual Core replay/current runtime/current permission and deterministic tool mapping. No alternate unvalidated effect path.

checkpoint payload {events}. Independently replay complete Core history, require pinned domain, require exact accepted prior prefix (same prefix is idempotent), reject shorter histories and forks. A durable checkpoint acknowledgement is the revocation/fence barrier. A local revocation alone gives no immediate remote guarantee. Any new accepted Core prefix invalidates queued work's earlier head; refreshing must be an explicit new prepare that revalidates the same original admission/current authority. For initial implementation, an attempt bound to a different checkpoint is refused; no automatic refresh/resend. Each different agent/role/session is checked against replay; generation is checkpoint head, not a per-agent numeric epoch.

prepare payload {operation}. Operation exactly {intentId,tool,arguments,businessKey,contractId}. Validate against the current checkpoint at destination trusted time. Deduplicate by domain-bound admitted idempotencyKey and complete normalized operation/fingerprint; changed bytes conflict. businessKey is application-supplied and binds one unique admitted intent; another intent using same businessKey conflicts even with identical args. Persist PENDING and admission checkpoint before replying. Capacity reserved at Core admission is not refunded by cancellation or failure.

commit payload {key}. Under the destination writer lock, re-read the durable current checkpoint and operation, require same checkpoint head as prepare, re-run validateOperation at destination now and require complete unchanged identity, then atomically record one synthetic effect and APPLIED report in the same durable state update. No external callback runs here: synthetic effect and dedup record share the storage boundary. A repeated commit/status returns the same report and cannot create another effect. Expiry, revocation/checkpoint update, terminated actor, changed tenure, malformed state or missing evidence fails closed. Pending remains pending on refusal.

cancel payload {key}. Under same lock, pending -> CANCELLED terminal with no synthetic effect; applied -> TOO_LATE report, cannot undo it. Unknown key -> UNKNOWN, never proof of no effect elsewhere. Cancel requires authenticated coordinator, and that authority is explicitly separate from agent grants. status payload {key} returns retained PENDING/APPLIED/CANCELLED or UNKNOWN, never causes execution. Keys and tombstones retained indefinitely in bounded local profile; exhaustion refuses new work rather than pruning. No automatic redelivery after UNKNOWN.

Durable store contract openDestinationStore({directory,initial}) -> {read(), transact(fn),close()}. Exclusive lifetime process lock, no age-based unlock. fn is synchronous; snapshot write uses temp+fsync+atomic rename+directory fsync, fail-closed parse/schema/integrity, bounded file. Only a successful committed mutation increments sequence. No response success before fsync. R04 adds verified restart/real kill/lock recovery/corruption/rollback evidence. Checkpoint retained at independent destination detects rollback of local broker history. Restoring an older valid destination snapshot after shutdown, even with its current identity marker intact, is outside this single-host anchor. The marker pins identity, not a monotonic sequence. Loss of all destination state is also outside this profile; never bootstrap over absent state using existing identity without explicit initialization. Identity persists and restart verifies configuration. No multi-host consensus claim.

Cooperative client createCooperativeClient({url,serviceId,coordinatorPrivateKey,servicePublicKey,timeoutMs}) exposes checkpoint(events),prepare(operation),commit(key),status(key),cancel(key), inspectResponse only validated data. Each call creates a new cryptographic nonce. The destination's authenticated assertion is retained separately; Core remote-report ACK is still NOT_PROVEN. A report from status can be recorded through R02 by a separately authorized current recorder.


R05 typed contracts may map amount/counterparty fields into the original signed Core declaration; absent projections remain absent. Amount is unsigned uint256 bigint, not a decimal string. The native JSON/framework boundary may explicitly convert validated decimal text. A registry allows one amount unit; applications must keep grant scopes dimensionally consistent across registries/services. No automatic currency conversion or independent counterparty identity proof is supplied.

A configured compensation tool requires a retained APPLIED original of its declared tool type, at the same service/contract. Its source business key is bound in committed arguments. Compensation has its own current authority/admission/business identity and never deletes, cancels or economically inverts the original by implication. Distinct compensation business keys can authorize distinct actions against one original; applications must define their intended business uniqueness.

E6 evidence review appends a signed complete-observation-set record, with explicit CLOSE_ATTEMPT_DUTY authority by the current assigned role occupant. It does not discharge the OPEN attempt duty. New observations and any later assignment invalidate current review status, even when the same assignee returns. This affects local evidence inspection; it neither asserts provider truth nor grants dispatch power.
