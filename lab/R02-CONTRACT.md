# R02 contract — observation and responsibility without renewed execution

Private experiment, 22 September 2026. Root decision under the accepted R02 scope. E1–E4 semantics and hashes are preserved. A new E5 genesis policy selects these events; old policies reject them. The E5 profile set is E4 plus the explicit semantic extension `continuity-attempt-observation-duty/1` in its policy hash. It is not a migration of old histories.

Three new canonical event families, with the existing full signed `administrativeAuthorization` wrapper:

1. `OUTCOME_OBSERVATION_RECORDED`: data exactly `{intentId, sourceAdmissionEventId, acknowledgment, actorId, administrativeAuthorization}`. Acknowledgment must be a valid REMOTE_SERVICE_REPORTED acknowledgment bound to the source admission, including its domain, head, intent, key and fingerprint. This is the current recorder's authenticated assertion that this report was retained; it authenticates neither the provider nor the report's truth. Multiple distinct report digests remain visible as DIVERGENT_REPORTS; this is disagreement in evidence bytes, not a judgment of fraud or a final outcome. Repeated identical digests can retain distinct recorder evidence.
2. `ATTEMPT_DUTY_CREATED`: data exactly `{record, actorId, administrativeAuthorization}`. Record exactly `{dutyId, sourceIntentId, sourceAdmissionEventId, durableRoleId, creationRoleTenureId, description, deadline, performanceAssigneeId, status:'OPEN'}`. One attempt-resolution duty per intent; duty IDs do not collide with legacy obligation IDs. Source is an actual admitted remote-report intent, not a declaration, consumption or receipt. Durable role is the original intent role. Creation tenure is the current tenure; creator and initial assignee are its current occupant. The duty remains OPEN; observing a report does not close it or prove underlying business fulfillment.
3. `ATTEMPT_DUTY_ASSIGNED`: data exactly `{dutyId, fromAgentId, toAgentId, actorId, administrativeAuthorization}`. From must equal the current assignee, to must be the current original-role occupant and the signed actor. Reassignment is an explicit administration event, not implicit succession or a source of authority. It may follow an independently valid role transfer and supports more than one handover. Immutable initial assignment/source facts remain.

Authorization for all three: use the current role/tenure of the original intent's durable role, its principal as required authority root, an exact current runtime signature and current ordinary permission. Actions respectively `OBSERVE_OUTCOME`, `CREATE_ATTEMPT_DUTY`, `ASSIGN_ATTEMPT_DUTY`; resource is the source intent ID. `termsCommitment` is the original intent commitment if present. No quantitative authority path may authorize these uncapped administrative transitions, matching the existing signed administration contract. Possessing a role, having a duty or possessing the old execution credential grants no permission. Original actor/session may be retired or terminated; the recorder's actor/session/tenure must be current.

All fields, including full acknowledgment/duty record and event ID/time, are bound by the existing domain-separated administrative challenge, exact replay head, proof and signature. Replay recomputes required authority; producer helpers cannot authorize raw forged events. Unknown, missing, undefined or over-limit fields fail closed. An async signer must be followed by exact-head and fresh-time/permission checks before append. A timestamp is observation/recording time, never a backdated remote-effect time.

Replay stores separate immutable `outcomeObservations` (map intent→all observations) and `attemptDuties` (map dutyID→creation record/current assignee/assignment evidence). These never change admissions, consumption, terminal outcomes, nonce usage, mandate capacity or invocation capabilities. An observed report cannot support a legacy execution receipt unless the original consumption rule was independently satisfied. The original unresolved intent remains unresolved in Core's execution lifecycle.

Public-shaped private API: `openLocalAttemptRecorder(options)` with `observe({id,intent,acknowledgment})`, `createDuty({id,intent,description,deadline})`, `assignDuty({id,duty})`. All are application-owned signed methods, not MCP endpoints. No method has an adapter, URL or dispatch callback. Inspection is separately read-only, based on independently replayed history, and distinguishes original actor from evidence recorder, durable bearer, initial/current assignee, stored evidence and external outcome NOT_PROVEN. SURVIVES gets E5-only `outcomeObservations` and `attemptDuties` arrays with evidence; older query output shape remains unchanged. The minimal SURVIVES projection omits free-text duty descriptions; the full-history inspector retains them.

Acceptance: late report after retirement recorded by separately authorized replacement with no new external effect/consumption; pending attempt can have durable duty before any report/receipt; explicit successive assignments preserve duty; report disagreements remain visible; wrong key, stale epoch, revoked/expired grant, foreign root, role-only, changed head during signing, wrong admission/ACK, duplicate duty, forged event and old-policy replay fail closed. All R01 controls/counterexamples and legacy regressions remain applicable. Duties have no discharge API in R02; closure, provider-authentication transport, destination fencing and cross-host consensus are separate stages.
